About

This add-on:

Completely eliminates the complex, cluttered, and difficult-to-navigate web interface of GitHub to deliver a seamless desktop experience for screen reader users.

Secure Account Connection (OAuth Device Flow),
Repository Management (Search, Create, Archive, Safe Deletion),
Branch Management (Switch, Create, Delete),
File and Folder Operations (View, In-addon Editing, ZIP Download, Upload Files and Folders, Rename, Move, Copy, Delete),
Commit History and Diff Review,
Pull Requests Hub and Merging,
Issue and Task Tracking (Templates, Attachments, Direct Actions, Copy Link),
Releases and Asset Distribution,
Exploring Public Repositories (Star, Fork, Direct Issue Reporting),
Notification Center,
Brings these and other essential GitHub capabilities directly to NVDA.

You can open the add-on via NVDA Menu / Tools / GitHub or the NVDA+G shortcut;
For feature requests or feedback, please contact m.aykurt38@gmail.com.

Account Connection and Security Architecture

The add-on implements GitHub's official OAuth Device Authorization Flow standard:

  • No Password Sharing: You never type your GitHub password into the add-on.
  • One-Time Verification Code: The connection dialog provides an 8-character verification code. Copy it using the Copy code button, open the approval page in your browser with Open GitHub approval page, paste the code, and approve. The add-on completes sign-in automatically.
  • Windows Credential Manager Storage: The granted access token is never stored in plain text on your hard drive. It is encrypted and saved securely inside the Windows Credential Manager.
  • Comprehensive Scopes: Essential scopes including repo and delete_repo are configured automatically to support repository management, file editing, issues, releases, pull requests, and safe deletion.
  • Disconnect Anytime: Remove the local saved key anytime via Account > Remove local connection from the main menu. This only logs out your local computer; your GitHub account and repositories remain completely unaffected.

Step-by-Step Account Connection Walkthrough

When the add-on is launched for the first time or after removing a local connection, follow these sequential steps:

  1. Account Setup Prompt: When pressing NVDA + G without an active account, a confirmation dialog appears: "No GitHub account has been added. Would you like to add an account now?". Focus is directly on the Yes button; press Enter to open the setup wizard.
  2. Obtaining and Copying Device Code: The "Connect GitHub account" dialog opens. With the public Client ID pre-configured, focus is directly on the "Start connection" (Alt+S) button; press Enter. The add-on requests an 8-character one-time device code from GitHub, placing focus directly on the code field once received. Press Tab once to reach "Copy code" (Alt+Y) and press Enter to copy it to clipboard. Press Tab once more to reach "Open GitHub approval page" (Alt+O) and press Enter to open GitHub's official verification page in your default browser.
  3. Browser: Account Confirmation and Entering Code: If you are already signed in to GitHub in your browser, the Device Activation screen displays your profile; click "Continue as <Username>" (or sign in if prompted). Next, the Authorize device page appears with focus in the input box; press Ctrl + V to paste the 8-character code, press Tab to reach "Continue", and press Enter.
  4. Authorizing Application Permissions: The authorization page displays the requested permissions (repository management, file and branch operations, releases, pull requests, and repository deletion). Navigate with Tab and click "Authorize <Username>".
  5. GitHub Security Confirmation (Sudo Mode / 2FA): Because elevated permissions are requested, GitHub enforces elevated security (sudo mode) displaying Confirm access. Enter your two-factor authentication code (Authenticator app, SMS, or email) or account password and click "Confirm".
  6. Setup Complete and Repositories Loaded: The browser announces "Congratulations, you're all set! Your device is now connected." and can be closed. In the background, the add-on immediately detects the authorization and automatically closes the connection dialog. The main window title bar updates to "GitHub — Connected account: <Username>". NVDA announces "Loading repositories…" followed by "X repositories listed.", and focus lands directly in the instant search box. The add-on is fully operational.

Main Window and General Navigation

Open or focus the add-on from anywhere in Windows with:

NVDA + G (or NVDA Menu > Tools > GitHub…)

When the main window opens, the title bar announces your connected GitHub username. The interface is engineered for optimal screen reader ergonomics and keyboard efficiency, arranged in the following Tab order:

  1. Search Repositories (Ctrl+F): An instant search input to filter your repositories by name.
  2. Repositories Tree (Left Pane): A tree view listing all repositories you own or contribute to. Navigate with Up/Down arrow keys.
  3. Branch Selector (Ctrl+B): A choice dropdown to switch between repository branches.
  4. Contents List (Right Pane): A detailed list displaying the files and folders (Name, Type) of the selected repository and branch.
  5. Menu Button (Alt+M): Opens the main menu organized into 5 clean submenus (Account, Repository, Branch, File, and Tools).
  6. Close Button (Alt+K or Alt+C): Safely closes the main window.

Essential Navigation Keys:

  • Tab / Shift+Tab: Cycles smoothly between Search box, Repository tree, Branch selector, Contents list, Menu, and Close buttons.
  • Enter (on Folder): Enters folder and displays its contents.
  • Backspace: Navigates up to parent directory and refocuses on the exited folder.
  • F5: Refreshes repositories or folder contents directly from GitHub.
  • Alt+M: Opens the full actions menu.
  • Alt+K (or Alt+C): Safely closes the dialog. (Escape is guarded in the main window to prevent accidental closure).
  • Applications Key (or Shift+F10): Opens a clean, context-specific menu scoped to the current focus (repository actions on repositories, branch operations on the branch selector, file/folder actions on contents).

Chapter 1: Repository, Branch, and Settings Management

Manage your repositories with complete control from the tree view or the main menu:

1. Instant Repository Search (Ctrl+F)

Press Ctrl+F to focus the search box. Typing keywords filters your repositories in real time, announcing the matching count. Case-insensitive and Unicode-friendly search ensures seamless matching. Press Down Arrow or Enter to enter the results, or Escape to clear.

2. Creating a New Repository (Ctrl+Shift+N)

Open the creation dialog with Ctrl+Shift+N. Set repository name (e.g. my-new-project), optional description, visibility (Public or Private), choose whether to initialize with a README, and optionally choose an open-source license from the dropdown selector (such as GNU General Public License v2.0 (GPL-2.0), GNU GPL v3.0, MIT License, Apache 2.0, BSD, or The Unlicense; default is None). Once submitted, the repository is created on GitHub within seconds and highlighted in your tree.

3. Repository Settings, Archiving, and Safe Deletion

Manage and delete repositories via the Repository menu or context menu (Shift+F10):

  • Description and Visibility: Update repository summary and switch between Public and Private in Repository settings….
  • Archive Repository: Check Archive this repository (make it read-only) to lock changes.
  • Safe Deletion: You can delete a repository either directly via Delete repository… in the Repository and context menus, or via the Danger Zone button in Repository settings…. The confirmation dialog requests the repository name to prevent accidental loss; you can type the name and press Enter or click I understand, delete this repository. Name matching is case-insensitive, immediately unlocking the delete action.

4. Inspecting Repository Details

Select Repository details… from the menu or context menu to review repository name, owner, description, default branch, visibility, archive state, star count, fork count, open issues count, web URL, and Git clone URL. Copy all metadata to your clipboard with Copy details.

5. Copy Repository Address and Open on GitHub

Choose Copy repository address to copy the HTTPS URL directly to clipboard, or choose Open repository on GitHub to view the project in your default web browser.

6. Downloading Repository as ZIP

Choose Download repository (ZIP)… to download the entire repository tree of the current branch as a clean ZIP archive.

7. Branch Management (Ctrl+B, Create Branch, Delete Branch)

Selecting a repository automatically loads all its branches in the background. Press Tab from the repositories tree or press Ctrl+B directly to reach the branch selection dropdown and switch branches using Up/Down arrow keys; the contents list and file operations immediately update for that branch.

  • Branch Context Menu (Shift+F10): While focused on the Branch selector, press Shift+F10 or the Applications key to access branch-specific actions: New branch…, Delete current branch…, and Refresh branches.
  • Create Branch: Select New branch… from the branch context menu (Shift+F10) or from the Branch menu to branch off from any existing branch. Full Git ref rules are enforced.
  • Delete Branch: Select Delete current branch… from the branch context menu (Shift+F10) or from the Branch menu to remove a branch. The default repository branch is strictly protected from deletion.

Chapter 2: File and Folder Operations

Perform direct file management on the selected repository branch:

1. Viewing and Reading File Content (Enter)

Pressing Enter on any code, script, or text document opens its full content in a native accessible text viewer. Read line-by-line with arrow keys, copy all content to clipboard with Alt+A, click Edit file… to switch into editor mode, or close with Alt+C (or Alt+K) or Escape. Binary files prompt you with an option to download directly.

2. Editing Files In-Addon (Ctrl+E)

Press Ctrl+E on any file in the contents list (or click Edit file… in the file viewer) to edit the file directly within NVDA. Make changes in the multiline accessible editor, enter a custom commit message, and press Ctrl+S or click Save to commit the updated file to GitHub immediately. Features a 5 MB file size safeguard and automatic SHA synchronization across consecutive edits.

3. Downloading Files and Folders (Ctrl+S)

Pressing Ctrl+S on any item in the contents list:

  • If a file is selected: Saves the file directly to your computer with its original name.
  • If a folder is selected: The add-on recursively packages all files and directories into a single folder-name.zip archive.

4. Creating a New File (Ctrl+N)

Press Ctrl+N to enter file name (e.g. notes.txt), commit message, and content, committing the new file directly to GitHub.

5. Uploading Files from Computer (Single or Multiple - Ctrl+U)

Press Ctrl+U, open the context menu (Shift+F10), or select File > Upload file(s) from computer… to upload a single file or select multiple files at once using standard Windows selection keys. The upload window remains open with a live progress bar, file counters, speech announcements, and a Cancel button. Upon completion, a summary report confirms the upload destination and count, and closing the dialog refreshes the directory listing.

6. Uploading Folders from Computer (Ctrl+Shift+U)

To upload an entire directory with all its subfolders and nested files to your GitHub repository, press Ctrl+Shift+U or choose File > Upload folder from computer…. Select the target folder from your PC; the add-on scans the full directory tree and confirms the total file count. During upload, the window displays live progress, speaks current file paths to your screen reader, and provides a Cancel button to abort anytime. When finished, a completion dialog summarizes how many folders and files were uploaded, and pressing Close automatically updates your repository contents.

7. Renaming and Moving Files or Folders (F2)

Press F2 on any file or folder in the contents list, open the context menu (Shift+F10), or select File > Rename or move… to rename the item or move it to a different directory in the repository:

  • Renaming a File or Folder: To change only the item name (e.g. from notes.txt to notes-v2.txt, or folder addon to extraSettingsAddon), edit the name in the prompt and submit. When renaming a folder, all nested files and subdirectories are automatically moved to the new location.
  • Moving to Another Folder: To move the file or folder into a new or existing directory, prepend the target directory path (e.g. archive/notes.txt or moving folder addon to src/addon). Moving a folder into itself or a subfolder of itself is safely guarded and disallowed.

The add-on preserves the exact file contents and directory hierarchy at the new destination, cleanly removes the old path, and refreshes the directory listing upon completion.

8. Copying Files and Folders (Ctrl+Shift+C)

To duplicate an existing repository file or folder to a new path without removing the original source, press Ctrl+Shift+C, open the context menu (Shift+F10), or choose File > Copy file or folder…:

  • Copying a File: Select a file (e.g. notes.txt) and copy it to a new location (e.g. addon/notes.txt) or simply enter a destination folder with a trailing slash (e.g. addon/). The original file remains untouched while an exact duplicate is created at the target path.
  • Copying a Folder: Duplicate an entire folder (e.g. doc) with all its nested files and subdirectories to a new directory (e.g. addon/doc). The source folder is preserved intact. Copying a folder into itself or a subfolder of itself is disallowed for safety.

Live progress is reported to your screen reader as each file is copied, and the contents list refreshes once the operation finishes.

9. Copying Item Path to Clipboard

Choose Copy item path from the context menu to copy the repository-relative path (e.g. src/utils/helper.py) to your clipboard.

10. Deleting a File (Delete)

Press Delete on any file to open the deletion confirmation dialog and commit its removal.

Chapter 3: Commit History and Unified Diff Review (Ctrl+H)

Track all code changes and project history directly inside NVDA:

  • Browsing Commits (Ctrl+H): Press Ctrl+H or select Tools > Commit history… to list commits on the selected branch with short SHA, commit message, author, and date. Press F5 to refresh.
  • Commit Details and Diffs (Enter): Pressing Enter on a commit displays the full message, modified files, addition/deletion line statistics (+/-), and full unified diff patches in an accessible text box.
  • Copy Details: Click Copy details to copy the entire diff patch and metadata to your clipboard.

Chapter 4: Pull Requests Hub and Merging (Ctrl+P)

Complete collaboration workflow without a web browser:

  • Listing Pull Requests (Ctrl+P): Press Ctrl+P or select Tools > Pull requests… to view pull requests with status (Open, Closed, Merged), author, branches, and creation date. Filter by Open, Closed, or All. Press F5 to refresh.
  • Opening a New Pull Request (Ctrl+N): Select source branch (head) and target branch (base), specify title and description, and submit the PR in seconds. Automatically verifies that at least two branches exist in the repository.
  • Reviewing PR Details and Code Diffs (Enter): Pressing Enter displays the PR body, changed files with full patch diffs, and chronological comment history.
  • Discussion and State: Post comments, close, or reopen pull requests directly from the dialog.
  • Merging Pull Requests: Click Merge pull request… on any open PR to merge contributions directly into your target branch with user-friendly conflict detection.

Chapter 5: Issues and Task Tracking (Ctrl+I)

Track issues, feedback, and milestones:

  • Listing Issues and Direct State Toggling (Ctrl+I): Press Ctrl+I or select Tools > Issues… to list open or closed issues with instant filtering. Directly close an open issue or reopen a closed issue from the list without entering the details dialog using the "Close issue" / "Reopen issue" button. Press F5 to refresh.
  • Copying Issue Link (Ctrl+Shift+C): Instantly copies the selected issue's GitHub web URL to your clipboard.
  • Issues Context Menu (Shift+F10 or Applications Key): Opens a contextual menu for the selected issue offering: View issue, Close / Reopen issue, Copy issue link (Ctrl+Shift+C), and Open on web.
  • Opening a New Issue and Template Support (Ctrl+Shift+I or Ctrl+N in dialog): Creating a new issue automatically discovers repository issue templates (both Markdown and GitHub YAML forms) and populates the body cleanly.
  • Collapsible File and Log Attachments: Attach logs, crash dumps, or text files directly via the "Add file…" button; files are embedded as accessible collapsible (<details><summary>) Markdown blocks.
  • Viewing Issue Details and Comments (Enter): View author info, creation date, issue description, and complete comment history in an accessible text box.
  • Adding Comments and State Toggling in Details: Post new comments and update issue state directly from the details view.

Chapter 6: Releases and Package Distribution (Ctrl+R)

Designed for NVDA add-on authors and open-source releases:

  • Browsing Releases (Ctrl+R): Press Ctrl+R or select Tools > Releases… to inspect published releases, release tags, and changelogs. Press F5 to refresh.
  • Publishing a New Release (Ctrl+Shift+R or Ctrl+N in dialog): Specify release tag, title, description notes, and attach an add-on bundle (e.g. .nvda-addon) to publish on GitHub in a single step.
  • Release Details, Asset Downloads, and SHA256 Copy (Enter): Read full changelog notes, download compiled packages directly to your PC with Download file…, copy the direct file download URL with Copy download link (Ctrl+C), or compute and copy the file's SHA256 checksum in seconds with Copy SHA256 hash (Alt+S or Ctrl+Shift+S) without needing to download the file to disk—essential for registering add-ons in JSON submission manifests. A context menu (Shift+F10) is also available directly on the downloadable files list.
  • Editing and Deleting Releases: Update tag, title, and release notes via Edit release…, or delete obsolete releases via Delete release….
  • Submit Add-on to NVDA Store… (Ctrl+Shift+S): Submit your NVDA add-on or new version directly to the official NVDA Add-on Store (nvaccess/addon-datastore). Automatically discovers the .nvda-addon asset download link, source repository URL, and version from your latest release, prefilling the official issue template form. You can complete submission in your browser with automated approval or submit directly via API.

Chapter 7: Explore GitHub Repositories, Starring, and Forking (Ctrl+Shift+F)

Explore the entire public GitHub universe:

  • Global Repository Search (Ctrl+Shift+F): Search all public GitHub repositories by keywords via Tools > Explore GitHub repositories… or Ctrl+Shift+F.
  • Inspecting Repositories (Enter): Review repository names, star counts, fork counts, primary programming languages, and descriptions. Press Enter to view full details and clone URLs.
  • Directly Report an Issue (Ctrl+N) or View Issues (Ctrl+I): Click "New issue…" (Ctrl+N) to submit a bug report directly to any explored repository without visiting the website, complete with templates and attachment support. Click "Issues…" (Ctrl+I) to explore its existing issues.
  • Search Results Context Menu (Shift+F10 or Applications Key): Context menu on any search result providing quick access to Repository details, Issues, New issue, Star/Unstar, Fork, and Open on web.
  • Star / Unstar: Star interesting projects or toggle star status with one click.
  • Forking: Click Fork to my account… to clone any open-source project directly to your GitHub profile.

Chapter 8: GitHub Notifications (Ctrl+Shift+B)

Stay updated with all activity on your repositories:

  • Opening Notifications (Ctrl+Shift+B): Select Tools > Notifications… or press Ctrl+Shift+B to list incoming notifications with filters for Only unread or All. Press F5 to refresh.
  • Intelligent In-Addon Routing (Enter): Pressing Enter or clicking View notification… opens pull requests directly in the Pull Requests hub, issues in the Issues dialog, and releases in the Releases dialog, automatically marking them as read.
  • Marking as Read: Press Space to mark a notification as read, or click Mark all as read to clear the list.
  • Open on Web: Open the discussion on GitHub in your web browser if desired.
